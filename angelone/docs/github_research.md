Honest gap: I found no active repo that publishes a net-of-cost NIFTY/SENSEX expiry-day options backtest, and none that tests OI/PCR as an expiry-day filter with data. Consistent with docs/options_research.md section 4.

## Ideas worth testing in our backtest (ranked)
Data we have: 5-min NIFTY/SENSEX index bars and VIX (data/idx, data/5min), daily stock bars. We lack historical option-chain OI/PCR/option prices unless noted.

1. **VIX regime gate + VIX-scaled size (from india-trade-cli).** Needs only data we have. Test: split expiry days by VIX level/VIX change from prior close (terciles, or <15, 15-20, 20-25, >25), report ORB15 net P&L per bucket on the index-move proxy and on our options_bt.py premium model. Also test "skip if VIX falls/rises > x% by 09:30". Accept only if the sign holds in both IS and OOS halves and on both NIFTY and SENSEX. Cheapest, so do first.
2. **Opening-range quality filters (our own, motivated by the brain skipping days).** Range width vs ATR/prior-day range, gap size at open, breakout bar volume/close-near-extreme. Test as rule-based filters in options_bt.py and compare against what the brain picked. If a simple rule reproduces the brain's filter, the LLM adds nothing; if no rule helps, skip.
3. **Daily-bar bias filter: trade only in direction of prior-day trend / 20-DMA / prior-day close position (CALLS_ONLY/PUTS_ONLY by rule).** Data on hand. Replaces the brain with a testable rule.
4. **Lower theta drag: later entry / hold-to-close variants and a time stop.** Expiry options decay fastest after ~13:00; test exit times 13:30/14:30/15:15 and entering only after the range break confirms at the 5-min close rather than intrabar. Data on hand (option model assumed; flag that premium path is modelled, not observed).
5. **Stoch RSI on 3/5-min as the expiry-day entry trigger (ui-trading-system).** Compare to ORB on identical days. Data on hand; likely overfit-prone, so require OOS.
6. **OI build-up matrix on index futures (order-flow):** price up + OI up = long build-up, etc. NEEDS historical index-futures OI at 5-min. We do not have it. Free EOD bhavcopy gives daily OI only: can test prior-day build-up as a daily filter for the next expiry day (weak but feasible). Intraday needs forward recording.
7. **Option-chain walls / max pain / PCR (order-flow, openalgo):** e.g. skip a call-side breakout if it runs into a large call-OI wall within x points; trade only when breakout clears the wall. NEEDS historical per-strike OI, which we lack. Plan: start recording option-chain snapshots at 09:30, 11:00, 13:00 on expiry days (SmartAPI or NSE feed) into a CSV for 8-12 weeks, then test. Until then, do not feed OI claims to the brain as if validated.
8. **GEX flip point (india-trade-cli/openalgo):** needs full chain with OI and IV history. Lowest priority; high complexity, no evidence.
9. **Risk-rule borrowings (no backtest needed):** daily loss cap and max orders/day (Kite skill, Agentic-Trader), GTT duplicate/stale monitor (ui-trading-system), position-guard check for unreviewed exposure. Add as asserts in options_paper.py / trader.py when going live.

## Takeaways
- Treat all repo claims as marketing: zero of nine showed a verified edge.
- The main practical gap between us and the leading repos is not strategy but data: they ingest live option-chain OI/Greeks; we do not record any. Recording it forward is the only path to testing OI/PCR/max-pain filters honestly.
- Our setup (paper-first, stops, kill switch, LIMIT-only, brain vs rules A/B journal) is already stricter than every repo reviewed. The brain-vs-bot A/B is the one real piece of evidence-gathering none of them do.
